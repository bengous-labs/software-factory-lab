# Routing

The Routing rules (`routing-rules.ts`), then the Routing judge (`routing-judge.ts`, its settings in `routing-judge.actor.ts`), with read-only tools under the guard (`shared/ask.live.ts`, `shared/tool-guard.ts`), set the Land route (`auto`, or `owner` with a Land approval) and the Review depth.
The Routing rules apply the routing policy of the factory config, `.github/software-factory.json`, which the Merge bot reads from its checkout of `dev`: an `ownerPaths` path (`.github/`; `REVIEW.md` and the `*.prompt.ts` files under `factory/`, the texts that guard the landing; `factory/install/logins.ts`, which says who counts as the Owner; `bun.lock` and `scripts/vendor/`, which the Code review does not read), and the config itself, sends the PR to the Owner; a `factoryPaths` path (the factory's code, `.claude/`, the agent docs and the build and gate configs) or a `deepReviewPaths` path (`app/src/store/`) gets a deep Code review and lands without the Owner (a light one when it only deletes files and those among them are Markdown or text) once `validate` and `mutation` are green and no Important is open; a PR that touches a path outside `factoryPaths` goes to the Owner on a breaking commit; past `lineCap` it gets a deep Code review and lands without the Owner.
The Routing judge, asked about the paths no rule names, sets their Review depth and whether a Patch delta is read again; it never sends a PR to the Owner, and neither does the Done judge.
The Owner holds any PR with a `land:human` label the Owner put; one the Merge bot's App or the Author's machine account set follows the route of each patch.
A PR reaches the Owner through these doors, and no other: an `ownerPaths` path or the factory config; a breaking commit on a PR that touches a path outside `factoryPaths`; an Important posted in round 3; a push after round 3 that needs a read, except one that answers round 3's Nits in their files and the test files beside them, on a PR that lands `auto`, which gets a Delta read instead (one in the Nit files alone needs no read); an Important that Delta read posts; a `land:human` the Owner put.
The Delta read keeps the Owner out of a push that renames a thing or adds the test `factory/roles/worker.md` asks of a Nit's answer, on a change three rounds already read, and still lets no push land unread.
A push after round 3 on a PR held for the Owner with an open Important also gets a Delta read, whatever its Routing answer, before the Owner is asked: it opens no door and closes none, since the PR is held already and stays so, but it closes the Importants it no longer reports, so the Owner approves knowing which still stand.
On a PR no one holds, an open Important owes no Delta read: it keeps the PR from landing until a round or a rejection closes it.

A change to a text a model reads lands through the Land loop like any other change: an `AGENTS.md`, a rule under `.claude/rules/`, `REVIEW.md`, a prompt, a hook's message.
The Routing rules send to the Owner the ones that guard the landing, `REVIEW.md` and the `*.prompt.ts` files.
