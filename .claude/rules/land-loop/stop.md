# The Stop hook

The Stop hook (`scripts/land-loop/stop/`, wired in `.claude/settings.json`) acts on the stop of an Author: a session whose environment holds `LAB_AUTHOR=1`, which the launcher gives through the `env` of the settings file it passes at launch. For any other session, and for a fork the hook launched, it logs why and does nothing. It publishes the branch checked out in the worktree the stop comes from, with a clean tree and a commit ahead of `dev`; it publishes nothing from the main checkout, a detached HEAD, `dev`, `main` or `lab/*`, nor a PR that is ready at this head, nor, when the branch has no open PR, the head one of its PRs had when it was closed without landing. A stop on a tree with uncommitted changes blocks once, asking for the commit alone; a later stop of the chain on a tree still dirty lets the session end. Claude Code marks every stop that follows a block, whatever the block said, so the hook leaves `.lab/state/commit-asked-<session>` when it asks for the commit, and the next stop reads it once: that block reported no failure, so the Author token, the Stop checks and the Done judge keep their own block after it, and a chain of stops blocks at most twice. It reads only the PRs opened from this repository, never a fork's of the same branch name. It runs `bun check` (the Stop checks), then asks the Done judge, a fork of the session, whether the change is finished, which question the Author's last message leaves to its user, and which of the App's open findings the Author rejects. A stop that leaves a question, finished or not, lands nothing and asks the Owner on GitHub: the hook sends a ready PR back to draft, pushes, opens the PR in draft when the branch has none, and posts the Done judge's whole question there as the machine account, with the branch, the session and a question mark (`QUESTION_MARK`); then it leaves the PR's relay, which brings the Owner's answer back to the session. A question stays open until a comment of the Owner in the PR's conversation follows it; a reply in a review thread does not close it. While one is open the hook posts no other, so a stop that repeats the question tells it once, and a finished stop with no question readies and pushes nothing, whether the PR is in draft or not, and leaves its relay again: the draft lands only after the Owner answers and a stop that leaves no question readies it. A stop on a PR ready at this head asks the Done judge nothing, so a question there is not seen. On a finished change that leaves none it replies in the thread of each rejected finding with the Author's reason and resolves it, pushes, opens or readies the PR, resolves the App's open Nit threads, and leaves the PR's relay; the stop then ends with no text. No reply it posts cites a commit: nobody declares a fix. It logs each step to `.lab/stop.log`, and one line per stop of an Author to `.lab/outcomes.log` of the main checkout: `published` with the PR, `asked` with the draft PR and its reason, or `not-published` with its reason. In an Author's session a PreToolUse guard (`scripts/hooks/refuse-author-publish.ts`) refuses `git push`, `gh pr create` and `gh pr ready`.
