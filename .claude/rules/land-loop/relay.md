# The relay

The relay (`scripts/land-loop/relay/`) is one detached process per PR, which the Stop hook leaves at a Publication, in the main checkout, and which outlives the session; a later Publication of the PR starts none while it runs. Every 30 s it reads the PR and delivers each Wake once, as a turn in the session of the PR's latest Publication: a failing check on the PR's head other than the App's own two (`agent-review` and `land-gate`, whose news the findings and the draft carry), a conflict with `dev`, an open Important or Nit finding, an Important a later round reports again, a comment of the Owner, the PR back in draft. The lab is public and a Wake starts a turn in a session that holds the Author's token: no other login's comment is delivered. It writes the Wake's lines on the session's messaging socket while the session runs, and resumes it with `claude --bg --resume <session-id> "<the lines>"` and no other flag when it no longer does. Claude Code hands a socket message to the session as another session's, never as its user's word, so a Wake that holds the Owner's words reaches a background session whose `claude agents --json` status reads `idle` by `claude stop <id>`, then the resume once the listing shows it stopped, since a resume before that starts a copy. It waits while the status reads `busy`; a turn that starts between that listing and the stop is cut, since Claude Code offers no stop that holds off a busy session. A session still listed running 30 s after the stop gets nothing: the Wakes stay pending, and the next poll resumes it once it shows stopped, or, while it is still listed idle, runs `claude stop` on it again; after three such stops in a row, the Owner's words go on the socket. A session with any other status or none, and an interactive one, which Claude Code cannot stop, get the lines on the socket. It ends when the PR lands or closes, which starts no turn, and writes its start and its end to `.lab/outcomes.log`. A relay that dies is not restarted: the log shows a start with no end.
